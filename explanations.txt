ПОЯСНЕННЯ КОДУ

Спільні частини запитів:
SELECT визначає, які стовпці або обчислені значення показати.
id і date залишають оригінальні ідентифікатор та дату замовлення.
AS задає зрозуміле ім'я стовпця результату, не змінюючи таблицю.
FROM mydb.orders вказує базу та таблицю; окремий USE не потрібний.
ORDER BY id впорядковує результати за ідентифікатором для зручної перевірки.
Крапка з комою завершує запит. Рядки з -- є коментарями.
Зворотні лапки навколо date позначають ім'я стовпця.

1. Частини дати
YEAR(date) повертає рік у стовпці order_year.
MONTH(date) повертає номер місяця у стовпці order_month.
DAY(date) повертає день місяця у стовпці order_day.
Разом з id і date результат містить рівно п'ять стовпців.
Наприклад, для замовлення 10248 дата 1996-07-04 дає 1996, 7, 4.

2. Наступний день
DATE_ADD(date, INTERVAL 1 DAY) додає один календарний день.
next_day — назва обчисленого стовпця.
Для замовлення 10248 результат — 1996-07-05.
Оригінальна дата в таблиці не змінюється.

3. Unix timestamp
UNIX_TIMESTAMP(date) повертає кількість секунд від 1970-01-01 00:00:00 UTC.
Дата без часу інтерпретується як опівніч у часовому поясі поточної сесії.
Тому на серверах з різними часовими поясами числовий результат може різнитися.
Під час перевірки @@session.time_zone = SYSTEM, @@system_time_zone = CET.
Для 1996-07-04 отримано 836431200.000000.
Нульова дробова частина — формат результату функції, не помилка.

4. Кількість замовлень у проміжку
COUNT(*) рахує рядки, які пройшли фільтр WHERE.
CAST(date AS DATETIME) перетворює значення на дату з часом тільки в запиті.
Це важливо: після CSV-імпорту date у цій базі має тип VARCHAR(50).
Без перетворення текст '1996-07-10' менший за '1996-07-10 00:00:00',
і текстове порівняння могло б помилково виключити нижню межу.
BETWEEN ... AND ... включає обидві вказані межі.
Результат: 72 замовлення від 1996-07-10 00:00:00 до 1996-10-08 00:00:00.

5. JSON
JSON_OBJECT приймає пари «ключ, значення».
'id' і 'date' у одинарних лапках — ключі JSON.
id і date без одинарних лапок — значення стовпців поточного рядка.
Для замовлення 10248 утворюється {"id": 10248, "date": "1996-07-04"}.
order_json — назва стовпця з цим об'єктом.

ПЕРЕВІРКА
Виконано 30.10.2026 у MySQL Workbench, сервер MySQL Community Server 26.7.0.
Таблиця orders містить 196 рядків, дати від 1996-07-04 до 1997-02-12.
Запити 1, 2, 3 і 5 повернули по 196 рядків; запит 4 — один рядок із числом 72.
Додатково перевірено всі 196 записів:
- немає дат, що не перетворюються на DATETIME;
- різниця між date та next_day дорівнює одному дню;
- зворотне перетворення timestamp повертає початкову дату;
- дата у JSON збігається з вихідним значенням;
- незалежний підрахунок через >= і <= також дає 72;
- на кожній межі проміжку є по одному замовленню, обидва враховані.
На скриншотах показані запити, початок результатів і статус виконання.
